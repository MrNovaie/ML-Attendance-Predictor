v0.4
- Un-record attendance (drag back to Not recorded + Save), with a forced model retrain after deletions.
- Self-service: a logged-in user can change their own attendance until 08:15 UTC+8, resets every day, enforced by the server.
- Login <-> person link, set by admins (now under People > Departments and logins).
- Tally at the bottom right ("In 3 · Partial 1 · Out 2 · Not recorded 1", then "(of 7)"), for admins and for users (counts only).
- "Today" is now judged in UTC+8, not the server's timezone. GET and PUT /api/attendance are admin-only.
- README updated to v0.4.

v0.5 (in progress)
- Backup: admins download everyone's attendance as one CSV (person, department, date, status) from the Backup section.
  Same file from the command line: flask --app app export-backup backup.csv
- Restore: flask --app app import-backup backup.csv [--replace] [--yes]. The whole file is checked first and written in one
  transaction, so a bad file changes nothing. Refuses a non-empty database unless --replace. Logins are not in the backup.
- Warning before un-recording: Save lists the people whose records will be deleted, with "Download backup first", "Cancel"
  and "Remove and save".
- Backend tests (pytest, tests/): 268 tests. Permissions on every route (a new route that is not listed fails the suite),
  accounts, attendance entry and un-record + model-cache clearing, the 08:15 cutoff and UTC+8 clock at their edges, links,
  the tally, predictions, database constraints, startup migrations, backup/restore. Checked by breaking the code on purpose:
  21 deliberate bugs, all caught.
- Admin screen split into three sections, each its own file: Record attendance (AttendanceForm.jsx), People
  (PeopleSection.jsx: "Add a person" + "Departments and logins"), Backup (BackupSection.jsx). "Add a person to track" is now
  "Add a person". Adding a person or moving a login link refreshes the Record attendance list without a page reload.
- README brought up to date (title, configuration table, CORS, backups-in-git warning, tests, new section names).

3. Multi-admin safety
   With 10 admins, two will eventually edit the same day, and the last save silently wins.
   - Record who changed or removed each record, and when. Admins will ask "who un-recorded Ben?".
   - Stop the last admin from being deleted or demoted.
   - Let the board refresh, or warn when it is stale.

4. The AM/PM split, before you go live
   It rebuilds a table, and that is much safer before real data exists than after.
   Start at STATUSES (attendanceUtils.js) and ALLOWED_STATUSES (app.py). The status CHECK constraint in users.py (0, 1, 2) means
   a table rebuild (test_schema.py has the constraint tests to update), and the ML status mapping, backup.py (allowed statuses)
   and the CSV import need updating too.

5. Deployment prep
   The .env settings, gunicorn, a Dockerfile, HTTPS, SQLite WAL mode and a scheduled backup.
   - Before running several gunicorn workers, make the model-cache write atomic. Two workers retraining at once can leave a
     half-written models.joblib.
   - .env, backend (backend/.env):  CORS_ORIGIN (now hard-coded http://localhost:5173), TIMEZONE_OFFSET_HOURS (8),
     SELF_SERVICE_CUTOFF ("08:15"), DEPARTMENTS (comma-separated) and DEFAULT_DEPARTMENT (Holding). SECRET_KEY, DATABASE_URL and
     ENV are already environment variables, they just have no .env file to live in yet.
   - .env, frontend (frontend/.env):  VITE_API_URL (now SERVER_URL in App.jsx, http://localhost:5000). Vite only exposes names that
     start with VITE_, reads the file when the dev server starts (restart it after editing) and bakes the value in at build time.
   - What does NOT move: STATUSES, ALLOWED_STATUSES and the status CHECK constraint. They have to change together, so a .env entry
     would let them drift apart. The seed CSV's expected column names (GOOD_HEADERS, in your import_csv.py) describe a file
     format, not a setting; leave them in code unless you have a reason.
   - How, so that it works:
       a. pip install python-dotenv (not installed yet; .env is already in .gitignore but nothing reads it). Add it to
          requirements.txt.
       b. Load it from backend/.env by path (Path(__file__).parent / ".env"), not the current directory, the same way the database
          path is resolved. Use load_dotenv(override=False) so a real environment variable still wins.
       c. Read the values inside create_app, not at import time, and give each a default equal to today's constant, so the app
          behaves the same with no .env at all.
       d. Validate at startup and fail with a clear message: offset is an integer from -12 to 14, cutoff matches HH:MM, the
          department list is not empty, the default department is in the list. A typo should stop the server, not shift the cutoff.
       e. Tests must not read your own .env: have conftest.py set the values explicitly (or pass a config dict to create_app),
          otherwise a local TIMEZONE_OFFSET_HOURS would break the fixed-clock tests.
       f. Commit backend/.env.example and frontend/.env.example with the default values and a comment on each; the real .env files
          stay ignored. Add the variables to the README's Configuration and Environment variables tables.
   - Check that it works: delete .env and confirm the app behaves as before; set a different cutoff, restart, and confirm the
     seconds left to the cutoff in GET /api/me/attendance change accordingly; set a bad value and confirm the server refuses to
     start; run pytest with a .env present and with none.
   - Not on the internet until items 1 and 2 are done: the CORS origin and SERVER_URL are hard-coded to localhost, and there is no
     CSRF protection or rate limiting.
