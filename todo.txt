v0.3
- Today's Attendance page, switched with a button fixed at the bottom left (view state in App.jsx, no router).
  It always shows today (no date picker, so the "future date" question no longer applies), has a department dropdown,
  In / Partial Day / Out columns, a Not recorded tray and a blue Save button (mouse, touch, keyboard).
- Departments: dropdown (Intelligence, Finance, Human Resources, Manpower, Headquarters), blank = Holding, NOT NULL.
- Predictions list refreshes after attendance is saved.

v0.4
- Un-record attendance (drag back to Not recorded + Save), with a forced model retrain after deletions.
- Self-service: a logged-in user can change their own attendance until 08:15 UTC+8, resets every day, enforced by the server.
- Login <-> person link, set by admins under Record attendance > Departments and logins.
- Tally at the bottom right ("In 3 · Partial 1 · Out 2 · Not recorded 1", then "(of 7)"), for admins and for users (counts only).
- "Today" is now judged in UTC+8, not the server's timezone. GET and PUT /api/attendance are admin-only.
- README updated to v0.4.

v0.5 (in progress)
- Backup: admins download everyone's attendance as one CSV (person, department, date, status) from Record attendance > Backup.
  Same file from the command line: flask --app app export-backup backup.csv
- Restore: flask --app app import-backup backup.csv [--replace] [--yes]. The whole file is checked first and written in one
  transaction, so a bad file changes nothing. Refuses a non-empty database unless --replace. Logins are not in the backup.
- Warning before un-recording: Save lists the people whose records will be deleted, with "Download backup first", "Cancel"
  and "Remove and save".
- Automated backend tests (pytest, tests/): 31 tests so far, covering the backup/restore only.
- README brought up to date (title, configuration table, CORS, backups-in-git warning, tests section).

4. Move settings that differ per machine into .env (after 1-3, so the tests exist to catch mistakes)
   What moves (backend/.env):  CORS_ORIGIN (now hard-coded http://localhost:5173), TIMEZONE_OFFSET_HOURS (8), SELF_SERVICE_CUTOFF
   ("08:15"), DEPARTMENTS (comma-separated) and DEFAULT_DEPARTMENT (Holding). SECRET_KEY, DATABASE_URL and ENV are already
   environment variables, they just have no .env file to live in yet.
   What moves (frontend/.env):  VITE_API_URL (now SERVER_URL in App.jsx, http://localhost:5000). Vite only exposes names that start
   with VITE_, reads the file when the dev server starts (restart it after editing) and bakes the value in at build time.
   What does NOT move: STATUSES, ALLOWED_STATUSES and the status CHECK constraint. They have to change together (AM/PM split),
   so a .env entry would let them drift apart. The seed CSV's expected column names (GOOD_HEADERS, in your import_csv.py) describe
   a file format, not a setting; leave them in code unless you have a reason.
   How, so that it works:
     a. pip install python-dotenv (it is not installed yet; .env is already in .gitignore but nothing reads it). Add it to
        requirements.txt when that exists.
     b. Load it from backend/.env by path (Path(__file__).parent / ".env"), not the current directory, the same way the database
        path is resolved. Use load_dotenv(override=False) so a real environment variable still wins.
     c. Read the values inside create_app, not at import time, and give each a default equal to today's constant, so the app
        behaves the same with no .env at all.
     d. Validate at startup and fail with a clear message: offset is an integer from -12 to 14, cutoff matches HH:MM, the
        department list is not empty, the default department is in the list. A typo should stop the server, not shift the cutoff.
     e. Tests must not read your own .env: have conftest.py set the values explicitly (or pass a config dict to create_app),
        otherwise a local TIMEZONE_OFFSET_HOURS would break the fixed-clock tests.
     f. Commit backend/.env.example and frontend/.env.example with the default values and a comment on each; the real .env files
        stay ignored. Add the variables to the README's Configuration and Environment variables tables (the Configuration table
        then stops saying "plain constants").
   Check that it works: delete .env and confirm the app behaves as before; set a different cutoff, restart, and confirm
   the seconds left to the cutoff in GET /api/me/attendance change accordingly; set a bad value and confirm the server refuses to start; run pytest with a
   .env present and with none.
   Note: a changed department list does not rewrite existing people (someone keeps a removed department until an admin changes it).
   Longer term, departments are data rather than settings; a department table managed from the admin screen would replace the
   env list.
